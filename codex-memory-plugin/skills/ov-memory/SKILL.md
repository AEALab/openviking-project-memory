# OpenViking 读取模式管理

使用本插件的确定性 CLI 管理配置，终端与 Codex 入口共用一套规则。仅修改用户要求的读取范围，不修改凭据、写入目标、插件启用状态或记忆数据。

## 入口

CLI 位于本技能目录的 [../../scripts/ov-memory.mjs](../../scripts/ov-memory.mjs)。根据当前实际加载的 SKILL.md 路径解析出脚本绝对路径，用 Node 执行；不假定 shell 已安装 `ov-memory`，也不假定存在 `PLUGIN_ROOT` 环境变量。

工具执行的工作目录必须是用户指明的目标目录；未指明时使用当前工作区。不要把技能或插件所在目录当作当前项目。

| 用户意图 | CLI 参数 |
|---|---|
| 查看当前配置 | `status` |
| 当前目录单库 | `read separate` |
| 当前目录双库 | `read combined` |
| 当前目录恢复继承 | `read inherit` |
| 修改全局默认 | `read separate --global` 或 `read combined --global` |

## 使用规则

- 用户只问如何配置时，解释命令，不执行切换。明确要求修改后才执行对应操作。
- 默认操作当前目录。只有用户明确要求全局默认时才加 `--global`，不能因一个项目的请求改动所有项目。
- 修改前先运行 `status` 核对工作目录、匹配规则和写入目标；使用 CLI 保存，不自行重写 JSON。
- `separate` 指当前目录对应的写入库，团队项目通常只读团队；不要把“个人库”自动解释为 `separate`。若用户要求“只读个人但写团队”，说明该模式开关无法表达，不擅自改写入连接。
- `inherit` 只移除当前目录规则，可能继续继承父目录，并不一定回到全局。
- CLI 校验失败时停止，汇报原因；不删来源、伪造 Key、改成另一个服务或绕过校验。
- 简短报告修改范围、配置有效模式、写入目标保持不变，以及自动备份位置。不要输出 Key。
- 这里的状态来自配置文件，不能据此宣称当前 MCP 进程已热切换。提醒重启 Codex 并新建会话；不要自动结束用户当前会话。
